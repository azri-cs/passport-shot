// PRIORITY ISSUES
P0

Preset selection is invisible

JS sets aria-checked on the preset radio buttons, but style.css:23 targets aria-pressed="true", which never matches. The selected preset looks identical to the unselected one. Sighted users cannot tell which spec is armed before pressing Start Camera.

FIX: Change the CSS selector to button[aria-checked="true"] (and align the hover/focus treatment), or switch the JS to aria-pressed. One line plus a state color.
P0

Capture errors are swallowed

main.ts btnCapture handler catches the error and only console.errors it. If capture fails (e.g., camera dies mid-session), the user sees nothing and is stuck in the live state with a dead camera. classifyCameraError returns canRetry which is never used.

FIX: Surface the capture error in a visible role=alert live region in the live state, and offer a retry affordance using the existing canRetry flag.
P1

Warning banner can never hide

main.ts toggles .hidden on bg-unavailable-banner, but no CSS rule defines .hidden for it (only .state.hidden and .processing-overlay.hidden exist). When background replacement is unavailable, the banner is permanently visible in the preview.

FIX: Add a bare .hidden { display: none; } rule, or scope it to the banner.
P1

No feedback during camera/model start

Start Camera disables the button but shows no progress while getUserMedia and the ~10MB model load run. On a cold connection this is a multi-second frozen screen with no indication of work.

FIX: Add a "Preparing camera..." state on the primary button or a thin progress region, and consider preconnect to the two CDN origins.
P2

Unmarked visual identity

The generic #2563eb blue and near-white canvas carry no chosen character for a photo tool. Nothing looks wrong, but nothing looks decided either.

FIX: A /design recolor + /design refine pass: pick a hue with a reason (photo/document context), build a real scale, and give the primary action a considered shape.
